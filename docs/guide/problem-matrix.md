# 가이드 — 문제 식별 매트릭스 (BLK-PROB-01)

> Phase E19 Phase 0 콘텐츠 갭 9 종 중 5 번째 신설. 사업계획서 **§2 문제인식** 작성에 필요한 4-축 × 3-단 매트릭스 + 도메인별 pain point + AS-IS 부족 원인 분석 통합 generator. 운영 가이드 군 16 번째 멤버. 4.26 자산 군 포맷 통일 (8 장 구조) 답습.

> 플레이스홀더 범례 — `[고객사]`·`[공정]`·`[수치]`·`[%]`·`[기간]`·`[변수]` 표준. **(확인 필요)** — 도메인 심각도 평가·기존 시스템 한계 정량화 등은 사용자 실측 후 §7 확정.

> 본 가이드의 직접 근거 — `track1_본문_공통Top5.md` BLK-T1-3.1 (인적 의존성) · BLK-T1-3.2 (데이터 단절); `track2_본문_공통Top5.md` BLK-T2-3.2 (모니터링 부재); `track3_본문_공통Top5.md` BLK-T3-3.1·3.2 (문서 분산·암묵지); 시나리오 5-단 구조의 "AS-IS 공백" 절 (40 SCN); `가이드_회사_프로필_템플릿.md` §1.3·1.4 (보유 시스템·R&D 인력) → 본 가이드 4-축 매트릭스 입력; 6 패키지 §2 본문 (6 도메인 문제 패턴 추출 원본).

## 1. 분류 — 문제 4 축 × 심각도 3 단

본 가이드는 사업계획서 §2 (문제인식) 의 정보를 발생 영역 (4 축) × 심각도 (3 단) 매트릭스로 분류한다. 4 축 = 운영·데이터·지식·제어. 한국 R&D 평가자가 "AS-IS 진단의 구체성·정량성·도메인 정합" 을 확인하는 핵심 영역.

### 1.1 운영 축 (Operational Pain)

`[고객사]` 의 생산·품질·안전·납기·원가 운영 측면 문제. 베테랑 의존·작업 편차·검사 한계·라인 정지·재작업·OEM 클레임 등. 본 축은 BLK-T1-3.1 (인적 의존성) 답습.

### 1.2 데이터 축 (Data Pain)

데이터 단절·품질·표준화·통합 측면 문제. MES-PLC silo·QMS 수기·비전 미디지털·OEM 데이터 격리 등. 본 축은 BLK-T1-3.2 답습.

### 1.3 지식 축 (Knowledge Pain)

암묵지·문서·노하우 측면 문제. 베테랑 은퇴·작업 표준 미문서화·문제 대응 분산·신입 학습 곡선 등. 본 축은 BLK-T3-3.1·3.2 답습.

### 1.4 제어 축 (Control Pain)

모니터링·드리프트·재학습·MLOps 부재 측면 문제. 기존 ML·자동화 시스템의 운영 정착 실패·드리프트 탐지 부재·재학습 SOP 부재 등. 본 축은 BLK-T2-3.2 답습.

## 3. §2 본문 6 절 템플릿

### 3.1 §2.1 운영 축 (~ 200 자)

> `[고객사]` 의 `[공정]` 공정은 운영 측면에서 `[운영pain]` 의 문제에 노출되어 있다. 구체적으로 `[운영근거]` (예: 베테랑 작업자 `[수치]` 명 의존 / 수작업 검사 오류율 `[%]` / 라인 정지 월 `[수치]` 시간 / OEM 클레임 연 `[수치]` 건) 가 정량 근거이며, 본 사업 AI 도입을 통해 `[목표]` 달성을 1 차 목표로 한다.

### 3.2 §2.2 데이터 축 (~ 200 자)

> 데이터 측면에서는 `[데이터pain]` 의 문제가 존재한다. `[데이터근거]` (예: MES-PLC 데이터 silo / QMS 수기 기록 `[%]` / 비전 검사 디지털 미저장 / OEM 사양 격리) 로 인해 AI 학습 가능 데이터 표준화·통합이 본 사업 phase 1 의 선행 작업이다.

### 3.3 §2.3 지식 축 (~ 200 자)

> 지식 측면에서는 `[지식pain]` 의 문제가 가중되고 있다. `[지식근거]` (예: 베테랑 `[수치]` 명 중 `[수치]` 명이 5 년 내 은퇴 예정 / 작업 SOP 문서화율 `[%]` / 문제 대응 노하우 분산) — 본 사업 Track 3 (LLM·RAG) 의 도메인 지식 추출·암묵지 디지털 자산화가 본 영역의 직접 대응.

### 3.4 §2.4 제어 축 (~ 200 자)

> 제어 측면에서는 `[제어pain]` 의 한계가 있다. `[제어근거]` (예: 이전 ML 도입 `[기간]` 후 운영 정착 실패 / 드리프트 탐지 부재 / 재학습 SOP 없음) — 본 사업 Track 2 (MLOps) 의 모니터링·드리프트 탐지·자동 재학습 트리거 도입이 본 영역의 직접 대응.

### 3.5 §2.5 종합 매트릭스 (~ 250 자 + 표)

> 4 축 심각도 매트릭스로 본 사업의 우선순위를 도출한다. 미해결 시 손실 추정 `[수치]` 억원/년 의 기회비용을 본 AI 도입으로 회수한다.

| 축 \ 심각도 | 낮음 (대응 여유) | 중간 (개선 필요) | 높음 (즉시 대응) |
|---|---|---|---|
| 운영 | | | `[운영심각도]` |
| 데이터 | | `[데이터심각도]` | |
| 지식 | | | `[지식심각도]` |
| 제어 | `[제어심각도]` | | |

### 3.6 §2.6 외부 압력 (~ 150 자)

> `[외부압력]` (OEM 품질 기준 강화·CBAM 탄소 보고 의무·중대재해 안전 책임 강화·경쟁사 AI 도입 격차) 가 본 사업의 시급성을 추가로 정당화한다. 외부 환경 변화는 본 사업의 phase 1 게이트에서 재평가한다.

- 운영 pain 의 정량 근거 (작업자 수·오류율·라인 정지 시간 등) — 사업 착수 후 실측

- 이전 ML 도입 실패 원인 — `[고객사]` 내부 회고
- 외부 압력 (OEM·CBAM·KOSHA) 기준 변경 — 매년 갱신
