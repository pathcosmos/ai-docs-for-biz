## §6 데이터·변수

본 사업의 핸들링 데이터는 **시계열 센서·정형 DB·이미지·비정형 문서** 의 4 카테고리로 구성된다. 시계열 영역은 ICS Historian·TSDB 에 1~10 초 주기로 수집되는 노 내 온도·분위기 가스·냉각 속도·열전대 응답·진공도 등이며, 정형 영역은 MES 작업지시·생산실적, QMS 검사 결과, ERP 수주·재고가 로트·작업지시 단위 키로 정합된다. 이미지 영역은 결정립 광학 현미경 이미지·표면 산화·뒤틀림 측정 가 Object Storage 에 코일·배치 단위로 보관되며, 비정형 영역은 SOP·CMMS 정비 이력·공정설계 Excel·설비 매뉴얼·KOSHA 가이드 등이 파일 서버·공유 폴더에 산재되어 있다.

**예측 변수 (X)** 후보는 도메인 지식과 데이터 과학적 기법을 결합한 다단계 피쳐 엔지니어링을 통해 설계된다. 첫째 도메인 지식 기반 피쳐로 패스 이력 누적값, 슬라이딩 윈도우 기반 롤링 통계 (평균·표준편차·최소·최대), 공정 구간 간 차분, 재질·레시피 메타 정보 결합 등을 채택하며, 둘째 자동 피쳐 생성으로 tsfresh·featuretools 등을 활용하여 잠재 피쳐 후보 풀을 형성하고, 셋째 상관관계 분석·상호정보량 (MI)·SHAP 기여도 분석을 통한 다단계 선정으로 통계적·모델 기반 양 측면에서 의미 있는 피쳐만을 최종 입력으로 채택한다. **목표 변수 (y)** 는 경도 편차·결정립도·잔류응력 을 중심으로 경도 편차 ±2 HRC·결정립도 ASTM 7 이상·잔류응력 200 MPa 이내 기준으로 정의된다.

**전처리·분할·거버넌스** — 결측·이상치·중복·단위 불일치는 표준 룰셋에 따라 처리하고, 라벨링은 품질 검사 결과·정비 이력·작업자 검수를 결합한다. 학습/검증/테스트 분할은 시간 기반 split 을 기본으로 하여 학습-추론 간 불일치 (training-serving skew) 를 방지하며, 동일 피쳐 정의를 학습 시점·추론 시점에 일관 관리하기 위해 **피쳐 스토어 (Feast 후보)** 를 도입한다. 데이터 거버넌스는 RBAC·감사 로그·리니지 추적·익명화 정책을 적용하여 IATF 16949·ISO 9001·SAE AMS·KS D 인증 체계의 변경관리 절차에 정합한다.

## §7 모델·학습

본 사업은 단일 알고리즘에 의존하지 않고 **문제 유형별 후보 모델 풀을 사전 정의하고 객관적 기준에 따라 채택 모델을 선정** 하는 모델 거버넌스 체계를 채택한다. 문제 유형은 ① 회귀 (품질 수치 예측), ② 시계열 예측 (공정 추이 예측), ③ 이상탐지 (설비 건전성 감시), ④ 분류 (비전 결함 판정·문서 분류), ⑤ 추천 (유사 사례·레시피 검색) 의 5 축으로 구분되며, XGBoost·LSTM·물리 기반 시뮬레이션 결합 (PINN)·CNN 가 1 차 후보군으로 등재된다.

채택 모델 선정은 다섯 가지 객관 기준을 동시에 적용한다. 첫째 **데이터 규모** — 라벨 보유량·세션 길이·표본 다양성을 평가한다. 둘째 **해석 가능성** — 심사·현장 수용성·규제 대응 관점에서 SHAP·Attention 등 설명 도구 적용 가능성을 검토한다. 셋째 **추론 지연** — 실시간 제어가 필요한 시나리오에는 100 ms 이하의 지연을 보장하는 경량 모델 또는 엣지 배포 가능한 구조를 우선한다. 넷째 **재학습 주기** — 데이터 드리프트 발생 빈도와 라벨 수집 주기를 고려해 재학습 비용을 산정한다. 다섯째 **현장 엣지 배포 가능성** — GPU·NPU 가용 자원과 운영체제 제약에 부합하는지를 확인한다. 모델 선정은 베이스라인 → 후보 모델 다중 학습·교차검증 → 채택 모델 결정의 3 단계로 진행되며, 각 단계 결과는 별도 평가 보고서로 산출된다.

단일 모델로 충분한 성능을 확보하기 어려운 시나리오에는 **앙상블 전략** 을 적용한다. 앙상블은 ① Stacking, ② Weighted Average, ③ Model Router 의 세 가지 패턴 중에서 시나리오 특성에 맞게 선택·조합한다. 검증 지표는 회귀의 경우 MAE·RMSE·R², 분류·이상탐지의 경우 정확도·재현율·F1·AUC, 시계열의 경우 sMAPE·시점별 잔차 분포를 다각 측정한다. 모델 성능 미달 시 데이터 전처리·피쳐 엔지니어링 재설계, 외부 AI 전문가 자문, 알고리즘 교체의 3 단계 대응을 사전 정의하여 리스크를 관리한다.

## §8 적용·배포

본 사업의 MLOps TO-BE 아키텍처는 **레지스트리·피쳐 스토어·파이프라인·서빙·모니터링·피드백·거버넌스의 7 종 구성요소** 를 모듈 단위로 표준화하여, [고객사 — 부산·경남 가상 중견 특수강 열처리 전문사 G] 의 가열로·연속소둔·진공 열처리·QT (퀜칭·템퍼링) 별·시나리오별 필요 모듈만 선택·조합할 수 있는 구조로 설계된다. ① 모델 레지스트리 (MLflow 후보) 는 학습된 모델의 버전·아티팩트·모델 카드·성능 지표를 단일 소스에서 관리하고, ② 피쳐 스토어 (Feast 후보) 는 학습용 Offline Store 와 추론용 Online Store 의 일관성을 확보하며, ③ 학습·재학습 파이프라인 (Airflow·Kubeflow Pipelines) 은 데이터 인출부터 배포 승인까지 전 단계를 코드화한다. ④ 추론 서빙 (BentoML·Seldon·Triton) 은 엣지·서버 이원 배포 및 카나리·섀도우·챔피언/챌린저 배포 패턴을 지원하고, ⑤ 모니터링 (Evidently·Prometheus·Grafana) 은 인프라·데이터·성능 3 층 감시를 수행하며, ⑥ 피드백 루프는 현장 태블릿 UI 의 작업자 정정 라벨을 학습셋으로 환류하고, ⑦ 거버넌스는 RBAC·감사 로그·리니지·모델 카드로 IATF 16949·ISO 9001·SAE AMS·KS D·ISO/IEC 42001 요구에 대응한다.

참조 아키텍처는 **엣지·온프레미스·클라우드 3 단 구조** 로 설계된다. 엣지 노드는 카메라·PLC 신호 수집과 경량 추론을 담당하고, 온프레미스 영역은 데이터 레이크·학습 파이프라인·모델 레지스트리·서빙·모니터링의 본거지이며, 클라우드 (CSAP 인증 국내 리전 우선) 는 대용량 실험 학습과 비실시간 추론을 보조한다. 데이터 흐름은 데이터 플레인·컨트롤 플레인·피드백 플레인 3 색으로 구분되며, OT ↔ IT ↔ 클라우드 경계에는 서명된 아티팩트·일방향 게이트웨이·TLS 인증서 기반 디바이스 ID 관리가 적용된다. 서비스 가용성은 99.5 % 를 목표로 하며, 추론 지연은 실시간 제어 100 ms 이하·HMI 경보 2 s 이하·RAG 질의 5 s 이하의 3 구분 SLA 를 각 서빙 계층에 매핑한다.

**HITL·교육·운영 통합** — AI 추론 결과는 [고객사 — 부산·경남 가상 중견 특수강 열처리 전문사 G] 의 기존 MES·SCADA·HMI 화면에 통합되어 작업자 의사결정을 실시간 보조하며, 작업자 검수·정정 응답은 라벨 DB 로 환류되어 재학습 데이터셋의 신선도를 유지한다. 도입은 섀도우 모드 (AI 추론은 수행하되 작업자 미노출, 모델 성능만 누적) → 권고 모드 (작업자에게 추론 결과 제시, 채택 여부는 작업자 결정) → 자동 모드 (정의된 임계 내에서 자동 실행, 임계 초과 시 작업자 콜백) 의 3 단계로 진행한다. 교육은 도메인 워크숍·HITL UI 실습·모델 카드 해석 교육의 3 모듈로 구성되며, 경도 균일화 예측·결정립도 추정·열처리 조건 추천 의 시나리오 운영 인력에 우선 적용한다.

## §9 MLOps loop

본 사업의 모니터링 체계는 [고객사 — 부산·경남 가상 중견 특수강 열처리 전문사 G] 의 가열로·연속소둔·진공 열처리·QT (퀜칭·템퍼링) 에 배포된 AI 엔진의 건전성을 **인프라·데이터·성능 3 층** 에서 동시에 감시한다. **인프라 층** — Prometheus 가 CPU·GPU·메모리·추론 지연 (p50·p95·p99)·처리량·에러율을 시계열 수집하고 Grafana 가 가시화하며 SLA 위반 시 자동 경보를 발생시킨다. **데이터 층** — Evidently 가 입력 피쳐 분포·예측 분포의 안정성을 PSI·KS·Jensen-Shannon 분포 거리 지표로 측정하며, 본 사업의 표준 임계는 PSI 0.10 이하 안정 / 0.10~0.25 주의 / 0.25 이상 재학습 검토로 채택한다. **성능 층** — 실측 라벨 기반 정확도·MAE·리콜·캘리브레이션을 측정하되 라벨 지연이 큰 시나리오에는 예측 신뢰도 평균·경보 빈도 등 프록시 지표로 보강한다.

드리프트 탐지의 핵심은 단순 통계 임계가 아니라 **임계·기간·비즈니스 영향 3 차원 결합 판정** 에 있다. PSI 가 단발적으로 0.25 을 초과하더라도 일정 기간 내 자연 회귀하는 경우 정상 변동으로 간주하며, 지속되거나 경도 편차·결정립도·잔류응력 등 비즈니스 KPI 의 동행 악화가 관측될 때만 재학습 트리거로 승격된다. 경보 채널은 Slack·이메일·SMS·HMI 알람의 4 채널 다중화이며, 심각도별 에스컬레이션 (Lv.1 담당자 → Lv.2 팀장 → Lv.3 임원) 을 사전 정의한다. 재학습 트리거는 ① 데이터 드리프트, ② 신규 결함 유형 출현, ③ 계절·환경 변화, ④ 설비 개·보수 이후 신호 특성 변화, ⑤ 현장 피드백 누적으로 특정 구간 정확도 저하의 5 대 패턴으로 정형화된다.

**운영 리듬** — 모델·시스템의 지속적 개선은 월간 모델 리뷰·분기 포트폴리오 리뷰·연간 거버넌스 감사의 3 단 리츄얼로 운영된다. 월간 리뷰는 PSI 추이·성능 지표·HITL 채택률을 정기 의제로 상정하고, 분기 리뷰는 시나리오 우선순위·재학습 비용·신규 시나리오 후보를 검토하며, 연간 감사는 모델 카드·리니지·거버넌스 정책 적합성을 외부 자문과 함께 점검한다. 본 운영 리듬을 통해 MLOps 성숙도 Lv.0 → Lv.2 로 단계적으로 끌어올리는 것이 본 사업의 종착 목표이며, 이는 [고객사 — 부산·경남 가상 중견 특수강 열처리 전문사 G] 가 단발성 AI 도입을 넘어 지속 진화형 AI 운영 역량을 내재화하는 기반이 된다.
